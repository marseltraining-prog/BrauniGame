## 1. Что за проект

Браузерная игра-симулятор: вы строите сеть пекарен-кофеен. Вся игра — **один HTML-файл** без интернета и без
зависимостей (чистый JavaScript, без фреймворков). Путь игрока:

1. **Пролог «Бариста»** (по желанию) — вы работаете у Рашида в кофейне «Калач», копите деньги (ход = месяц).
2. **Стадия 1 «Своя кофейня»** — одна точка «вблизи», цель главы → переход в сеть.
3. **Первый акт** — сеть в стартовом городе (по умолчанию Уфа). Победа: оборот сети за 12 месяцев ≥ 5 млрд ₽.
   Сильный игрок побеждает примерно на **15-м году** при 30+ точках; средний — заметно дольше; слабый — рискует банкротством.
4. **Второй акт «Россия»** (с ~9-го года) — 19 городов, директора, штаб, логистика; цель «Федеральная сеть».
5. **Третий акт «Холдинг»** — три финала на выбор (биржа / за рубеж / франшиза-империя). Сделана только «биржа», она в отдельной ветке (см. §6).

Сквозь всю игру идёт **сюжет**: герои Рашид, Гуля, Олег, Эльвира, семья. В нём 123+ сцены, развилки меняют правила, семь концовок.

Репозиторий: https://github.com/marseltraining-prog/BrauniGame, ветка `main`.
У владельца на Mac: `~/dev/BrauniGame` (полный путь `/Users/macbookmarsel/dev/BrauniGame`).

## 2. Как запустить, собрать и проверить (Mac владельца)

```bash
cd ~/dev/BrauniGame
export NODE_PATH=~/.bk-tools/node_modules     # там стоят playwright (Chromium + WebKit) и terser
node build.js            # → dist/local.html (открыть в браузере) и dist/khlebnaya-karta.html
node build.js --min      # + сжатая dist/khlebnaya-karta.min.html и полный dist/khlebnaya-karta-<версия>.html
open dist/local.html     # поиграть
```

- Сборка — `build.js`: склеивает файлы из `src/` **в порядке списка** в `build.js` (новый файл — добавить в этот список
  и в `sim/load.js`, иначе его не увидят ни игра, ни боты).
- **Боты** (Node, без браузера): `sim/*.js`, грузят игру через `sim/load.js`.
- **Браузерные проверки** (Playwright): `qa/*.js`. Ждать «0 проблем, 0 ошибок консоли». `BR=webkit` — проверка в Safari-движке.
- **Полная проверка выпуска**: `node tools/check-release.js` (все проверки по очереди, ~1–2 ч), затем
  `node tools/check-release.js --retry-failed`. Отчёт пишется в `docs/releases/<версия>-checks.json`.
  `BK_CHECK_TIMEOUT=<мс>` — лимит на одну проверку.
- **Проверки запускать строго по одной**, не параллельно: под нагрузкой браузерные проверки ложно падают.

Главные эталоны:

| Команда | Должно быть |
|---|---|
| `node sim/bot.js good 3 18 --summary` | `wins 3/3`, медиана ~14,7–14,9 года (сейчас 14.8) |
| `node sim/bot.js good 12 22 --summary` | 11/12 побед (один сид всегда банкротится на ~2,5 году — так и было), медиана ~14,4–14,8 |
| `node sim/bot.js avg 8 28 --summary` | медиана ~21–23 года |
| `node sim/bot.js bad 4 6 --summary` | все банкроты |
| `node sim/newbie.js 8 2` | 0/8 банкротств |
| `node sim/corp.js 2 16` | «деньги сходятся каждый день, NaN нет» |
| `node sim/corp-calib.js 3` | «Калибровка в допуске» |
| `node sim/story.js --check` | «Всё в порядке» |
| `node sim/rewind.js 2 5` | «всё совпало» |
| `node sim/stage1.js ideal,normal,weak 12` | ideal 12/12, normal ~11/12, weak — трудно (это нормально) |

Полный список проверок с описанием — HANDOFF.md §3 и список в `tools/check-release.js`.

## 3. Как устроен код

- Всё в пространстве имён `BK` (`var BK = globalThis.BK || ...`). Каждый файл — самовызывающаяся функция.
- **`src/config.js`** — все числа баланса (`BK.CFG`). Баланс меняй **здесь**, а не в формулах.
- **`src/engine.js`** (`BK.Engine`) — чистая логика без DOM, детерминированный ГСЧ. Состояние игры — один объект `S`.
  `newGame(opts)`, `tick(S)` — один игровой день. 1-го числа — месячный расчёт (`monthly`).
- **Модули подключаются обёрткой**, движок почти не трогают: модуль сохраняет `BK.Engine.tick` и подменяет его своей
  функцией (до/после дня). Так сделаны: достижения, вехи, тренеры, управляющие, рост, залог, инвесторы, сюжет, «Переиграть».
  Новый модуль делай так же.
- **Своё состояние модуля** — `S.<модуль>`. Создавать только когда механика началась, а для старых сохранений
  ставить значения по умолчанию через `ensure()`. **Своя ГСЧ у модуля** (`S.<модуль>.rng`), чтобы не сбивать
  поток случайностей движка: иначе меняются все партии ботов.
- **Интерфейс** — `src/ui/*.js` + `*.css`. В `panels.js` / `app.js` / `map.js` — только короткие хуки.
- **Данные**: `src/data/` (районы, события, сюжет, города, карты городов `city-<id>.js`).
- **Второй акт**: `src/corp.js` (города, упаковка неактивных городов в «агрегат»), `src/directors.js`,
  `src/corphq.js` (штаб), `src/corpev.js` (события). Неактивный город считается раз в месяц упрощённо
  (`cityMonth`), активный — подробно по дням. Агрегат откалиброван: расхождение с подробным расчётом в пределах нескольких процентов.
- **Сюжет**: `src/story.js` + `src/data/story*.js`. Сцена = триггер (условия по состоянию) + реплики + варианты с эффектами.
  У реплик бывают `views: [{ when:[условия], text }]` — текст под ситуацию. Источник истины по сюжету — `docs/story.md`.
- **Кофейня**: `src/stage1.js` + `src/ui/stage1.js`. **Пролог**: `src/prologue.js` + `src/ui/prologue.js`.
- **Сохранения**: `localStorage`, 3 слота, сжатие (`src/savecodec.js`) при нехватке места, «Код сохранения» для переноса.

Подробный путеводитель по каждому файлу и механике — **CLAUDE.md** (раздел «Как устроен проект» и ниже; несмотря на имя, это
общий документ проекта). Механики для игрока — **GDD.md**. Второй акт — `docs/russia-design.md`.

## 4. Железные правила (не нарушать)

1. **Старые сохранения игроков должны открываться.** Не переименовывать экспортируемые функции и поля `S.*`.
   Новые поля — с безопасным значением по умолчанию.
2. **Подробные карты городов — только для новых партий.** Старые партии остаются на прежней карте (`mapGen: 1`),
   новые получают `mapGen: 2`. До подключения карты снять старые сохранения:
   `node tools/capture-legacy-city.js <город> <версия>`. Порядок нового города — см. §7, шаг 3.
3. **Боты первого акта побайтно прежние**, если задача не меняет баланс намеренно. Если меняет — измерить до/после
   и записать числа (в release notes и HANDOFF). Требование владельца: сильный игрок — ~15 лет.
4. **Версия — всегда 0.9.x «бета»** (`BK.CFG.VERSION` в `src/config.js`). 1.0 — только по слову владельца.
5. **Без интернета**: никаких внешних адресов, шрифтов, библиотек. Всё внутри файла.
6. В подсказках вариантов выбора — только **область и сила** последствия («Гости · умеренно») и реальная цена.
   **Не возвращать** ▲/▼, «лучше/хуже» и цвет-оценку.
7. Все тексты — по-русски, в духе уже написанного (`docs/writing.md`). Тяжёлые темы (болезнь, смерть) — только как в `docs/story.md` (без подробностей, через заставку).
8. Решение, которое зависит от владельца, **не выдумывать**: записать вопрос в `docs/waiting-owner.md` с вариантом по
   умолчанию и делать дальше независимую задачу.
9. После каждого законченного этапа: обновить HANDOFF.md, PLAN.md (отметить), GDD.md/CLAUDE.md при изменении механик →
   `node build.js` → проверки → `git add -A && git commit && git push origin main`. **Не считать сделанным без push.**

## 9. Решения владельца (главное) и открытые вопросы

Все решения с датами — в `docs/waiting-owner.md`. Главное:
- Честная география: подробная карта может замедлить победу в городе на 1–2 года, это нормально.
- Направления роста в чужих городах ведёт директор сам и только в городах с 10+ точками. Кнопок для игрока нет.
- Холдинг — три финала на выбор: биржа, за рубеж, франшиза-империя.
- Частоту сцен в первом акте пока не трогать: владелец сам проверит.
- Аудит D1–D4:
  - D1: помощь при переходе остаётся, но об ней честно пишется;
  - D2: статистика продуктов подписана «примерно»;
  - D3: короткий путь через 450 дней убран, вместо него подсказка «Что мешает»;
  - D4: календарь не двигается, пишется «Прошло N лет».

**Открытый вопрос:** когда открывать холдинг (по умолчанию — через 14 дней после победы первого акта).

## 11. Ловушки, на которых уже обжигались

- **Порядок случайных чисел.** Любой лишний вызов общего ГСЧ (`S.rng`) меняет все партии ботов. В новых модулях использовать свою ГСЧ.
- **Упакованные точки второго акта** собираются литералом `canonStore` в порядке `PK_KEYS` (в `src/corp.js`). Нельзя присваивать поля по списку: V8 превратит ~1000 объектов в медленный «словарь». Отсутствующее поле — `undefined`, не `delete`.
- **Сюжет в ботах выключен** (`BK_STORY=1` включает). Вехи и инвесторы — тоже (`BK_MILES=1`, `BK_INV=1`).
- **Сборка `dist/` и `README.md`** меняются при каждом `node build.js`. При конфликтах слияния просто пересобрать.
- **Числа в репликах сюжета.** Не писать в тексте сцены конкретное число («четыре точки»), если сцена может прийти раньше. Брать число из игры через `views`.
- **Под нагрузкой** (параллельные прогоны) браузерные проверки `qa/rewind.js`, `qa/full.js` и `qa/pixel.js` (замедление CPU×4) падают ложно. Повторить по одной.
