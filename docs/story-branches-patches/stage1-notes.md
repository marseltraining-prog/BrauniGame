# Stage1 fixture: натуральные триггеры карточек

Обновлён `sim/story-stage1-fixture.js`; изолированная копия — `tmp/story-branches/stage1/fixture.js`.
Эта ревизия не проверялась запуском агентом. Родитель выполняет последовательную runtime-проверку.

## Исправленная достоверность

Предыдущая ревизия вызывала queue для s13/s15/s17 на day0. Stage1 проверяет seen по truthiness; day0 после ответа оставался ложным. Родитель обнаружил повтор s13/s17 на естественных днях47/127 и итог Oleg+60 вместо ожидаемых+30. Такой результат не считается законным покрытием.

Новая ревизия полностью удаляет explicit queue admission. Карточки s13/s15/s17 приходят только из Stage1 через реальные Engine.tick. Их варианты выбираются по фактическим label: «Договорились», «Продавайте. Вы заслужили отдых», Айдар/Лариса (либо доступная Гуля). Динамические индексы не фиксируются.

Каждый из трёх target должен разрешиться ровно один раз и на положительном day. Второе появление — ошибка ДО применения повторного эффекта. До openSecond проверяется, что все три уже были разрешены ровно однажды. После finish повторно проверяются counts и положительные даты в Stage1.seen/Story.seen. Ничего в этих реестрах не записывается вручную.

## API и помощь coverage

start → spotCost/spotPreview → pick → setHours/setDayOff/setPrice → Engine.tick/card/choose → настоящая ready → openSecond → s18:0 → finish → chooseProduction → play.

Состояние приходит после настоящего completed prologueState. Helper не пишет story.f/seen, Stage1.flags/status/streak/months, store.status/openDay или day вручную. Не форсирует очередь и готовность.

Опциональный cashFloor сохраняется как assisted coverage с before/after/injected/reason для каждого вливания. CFG.STORY.ON временно выключается во время Stage1, чтобы обычный сетевой Story.tick не играл поверх кофейни; фиксируется в ledger и восстанавливается finally. Это остаётся технической помощью, не каноническим балансом партии.

maxDays900; если натуральная ready или target отсутствуют, результат — ошибка с counts, не подделка состояния. Если ready наступила до всех целей, helper продолжает реальные ticks и ждёт оставшиеся карточки. Enemy mentor несовместим с натуральным письмом s17 и отклоняется.

Лариса выбирается через реальные динамические варианты; laraSpy приходит от настоящего Stage1 RNG. Если requireSpy=true, а RNG дал false, результат — ошибка. Caller должен взять совершенно новый пролог/state с новым seed и сохранить поиск seed в ledger. Не выставлять laraSpy руками.
